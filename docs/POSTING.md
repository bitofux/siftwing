# 原始 Posting 合同

`siftwing_posting` 只公开依赖基础层；公共权威为
[posting.hpp](../include/siftwing/index/posting.hpp)。`Posting` 表示一个词在一个文档中的关系：
拥有 `DocumentId` 和正 `uint64_t` 原始出现次数。词身份由外层词典/列表调用方关联。
本类型不携带 TermId、文档长度、DF、浮点权重或词位；语料级组合由[倒排索引](INVERTED_INDEX.md)提供。

`Posting::from_count(document,count)` 保留源整数类型，再无损转换为 uint64；零/负值及
不可表示值用 Result 失败返回，context 为 `posting.tf`。bool、浮点、枚举和强 ID 次数
在实例化时拒绝。完整 1—UINT64_MAX 次数合法，文档 ID 的 0/UINT64_MAX 也合法；
调用前已发生的截断、回绕或错误重新包装无法追回。成功不证明次数来自真实文本、ID
存在/去重保留或属于指定快照，也不验证 TF 小于等于文档总词数。普通失败无部分关系，
诊断分配和未知异常向上传递。没有默认构造或公开未受检构造，不用零次数表示不存在。

复制/移动/赋值保持完整有效整数对，移动源保留原值、自赋值合法。两个 getter 按值返回，
不会借用临时对象。相等比较同时检查 ID 与 TF；排序调用方显式比较 document_id，
不把 TF 当次序。赋值替换完整关系，无单字段 setter。

`PostingList` 是可变 `vector<Posting>`，别名自身不保证有序或唯一。
`validate_posting_list(list,limits)` 同步借用、先要求正 `max_postings`，再校验条数，
最后检查文档 ID 严格递增。空列表合法（仍须正配置）、等于预算合法；重复 ID 即使
次数不同也拒绝，不自动排序、合并、累加 TF 或修改输入。context 为
`posting.limits/size/order`，次序失败给出首处不递增的 0 基元素位置。
success<void> 只证明校验时的局部结构，不冻结列表；之后修改须重新校验。
校验不保存借用，调用期间列表/配置不得失效或并发写。

列表不携带词、快照或语料身份，也不保证每项都来自同一个词。只有调用方保证完整的
同词列表来自同一搜索保留集合时，唯一文档关系条数才能解释为该词 DF；本模块不计算
DF、N、TF-IDF 或归一化。例：某词在 doc7/doc42 各出现 2/3 次，对应两项 TF=2/3，
关系数为 2，累计次数为 5；推荐重复交付可能另有累计次数，不能回填单文档 TF。

Posting表示原始计数，权重公式和零向量合同由WeightedIndex定义；本类型不包含浮点
权重或磁盘/网络布局，组合调用不改变其TF语义。
不实现倒排构建、AND/OR、打分、词位、候选推荐或持久化。校验复杂度 O(条数)、
成功路径无列表复制；预算不计已有装载/容器容量，不是硬内存/CPU限制。
无 IO、共享可变缓存或新第三方库，未实测并发；同对象写入由调用方同步。
