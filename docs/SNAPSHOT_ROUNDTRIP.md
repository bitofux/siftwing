# 快照往返验收

`snapshot.roundtrip` 是由 CTest 注册的集成测试，使用现有 Writer、Reader、文本与索引接口，
没有新增生产API、文件格式或第三方依赖。运行于构建目录下的独立新输出位置，使用原创输入；
成功只清理本次测试创建的目录，失败保留目录并输出准确路径及命令诊断。

固定输入身份、记录、原TF、独立推荐频次、构建版本和来源声明，在同一数值环境下，
两次独立进程构建的八文件须逐字节相同；反转记录及词频输入排列也须相同。
再由独立进程加载所有部件，保持原元数据，交给真实Writer发布到新父目录，
八文件须相同，重启Reader后再次核对完整记录、规范权重和推荐字符关系。

版本是显式元数据：只改变SnapshotVersion时，六payload保持相同，manifest身份和COMPLETE
绑定相应变化。测试分别验证这些字节，不能把不同版本的完整目录称为相同。
已有版本拒绝覆盖且原产物保持；错误请求版本、截断和未知格式的加载失败不产生再发布输出。

32组固定种子原创集合覆盖空支路、显式空篇、独立推荐交付数、稀疏/0/UINT64_MAX文档身份、
词频及记录排列、NUL/非UTF8原记录字节、可选来源字段缺失与提供空、非BMP及组合字符词键。
复用已有Python `struct/zlib/hashlib` 的独立记录/偏移/CRC/摘要参考，以及整数统计、Unicode
标量关系和数学参考；浮点参考使用容差，同环境真实产物比较使用精确字节，两者分开。

另一个原创接线批次每次重新创建TXT/RSS适配器和英文文本管线：TXT处理BOM/CRLF，RSS
抽取HTML正文与来源元数据；停用词过滤后计算SimHash，按来源次序进行阈值0的真实去重。
两篇正文词频相同的文档只保留第一篇搜索记录，全过滤条目不进入搜索；推荐明确累计四次
交付，包括重复及空TF。搜索N=2、总TF=5、posting=4，推荐交付数4、总频次8。
两次重新读取和构建、反转输入及候选排列、加载与再发布均须保持语义与规范字节。
独立参考手写预期抽取正文和来源字段，并核全部六payload、manifest与COMPLETE。

运行方式（先完成对应构建）：

```sh
ctest --test-dir build/debug -R '^snapshot.roundtrip$' --output-on-failure --no-tests=error -V
ctest --test-dir build/release -R '^snapshot.roundtrip$' --output-on-failure --no-tests=error -V
```

测试探针只为验证而组合部件，不是生产indexer或CLI。真实接线使用英文路径；中文/混合
分词的原模块测试仍单独保留。本测试没有使用原始私有业务语料，也不证明词频/来源声明的
真实性、推荐质量、性能、全部并发时序、网络文件系统或断电恢复。确定性遵守现有
binary64、FE_TONEAREST、固定策略和CPU/libm兼容前提，不承诺跨架构逐位一致。
