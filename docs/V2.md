# V2 在线服务工程基线

V2 将[离线检索核心](V1.md)接入 C++17/Linux Main-Sub Reactor：正式入口为
`siftwing-indexer`、`siftwing-server` 和 `siftwing-cli --network`。本页给出公开输入的运行、
验证和小型基准入口；实际阶段验收与学习掌握分别需要证据。

V2后的兼容扩展提供[JSON启动配置](SERVER_CONFIG.md)，旧CLI示例保持可用；默认loopback，缓存和请求/空闲期限仍默认关闭。

## 数据与控制链路

```text
peer TCP → Main accept4 → 有界 fd 移交 / eventfd → 所属 Sub / Connection
  → 24 字节头 + JSON → 单在途门禁 → 有界 WorkerPool
  → SearchService / 只读快照 / 可选 LRU → 拥有 Completion / eventfd
  → 原 Sub 的 ConnectionId / generation / request_id 校验 → 有界输出 → peer
```

Main 负责接入和轮询移交；Sub 独占连接、身份表、读写与期限。worker 只持拥有请求、只读
服务及结果发布目标，不接触 Connection 或 socket。PING/SERVER_INFO 直接在 Sub 响应；
SEARCH/SUGGEST 才进入 worker。完整交付至响应排空保持一个在途请求，缓存后续帧按序推进。
正常关闭先停止接入/新任务，限时排空网络，再等待全部 worker、通知发布和 Sub 回收；
网络截止不取消任务，也不是 join 的硬上限。详见[线程拓扑](THREAD_TOPOLOGY.md)和
[优雅退出](GRACEFUL_SHUTDOWN.md)。

## 从公开输入运行

在仓库根目录按 [README](../README.md) 构建 Release。以下输入均来自原创 MIT 夹具，
输出使用全新目录，不读私有资料；端口9000须空闲。终端一：

```sh
v2_output=$(mktemp -d /tmp/siftwing-v2.XXXXXXXX)
v2_source=$(git rev-parse HEAD)
build/release/siftwing-indexer \
  --output "$v2_output" --version 1 --build-version "$v2_source" \
  --search-txt tests/fixtures/golden/txt/en-river.txt \
  --search-rss tests/fixtures/golden/rss/original.xml \
  --recommendation-txt tests/fixtures/golden/txt/en-workbench.txt \
  --recommendation-rss tests/fixtures/golden/rss/original.xml
build/release/siftwing-server --snapshot "$v2_output" --version 1 \
  --port 9000 --subs 2 --workers 4 --task-capacity 128 --shutdown-ms 1000
```

看到 `PORT 9000` 后，在终端二执行：

```sh
build/release/siftwing-cli --network PING --port 9000
build/release/siftwing-cli --network SERVER_INFO --port 9000
build/release/siftwing-cli --network SEARCH --port 9000 --query lantern --top-k 5
build/release/siftwing-cli --network SUGGEST --port 9000 --key lantern --top-k 5
python3 tools/v2_baseline.py --port 9000 --command PING
python3 tools/v2_baseline.py --port 9000 --command SEARCH --query lantern
python3 tools/v2_baseline.py --port 9000 --command SUGGEST --key lantern
```

终端一用 Ctrl-C 正常关闭，检查退出码及最终报告。`build_version` 是建库方声明的身份，
服务不认证该字符串；未提交源码须另存 diff/哈希，不能只凭此字段证明二进制身份。
端口0可由内核分配，客户端使用服务实际报告的端口。服务默认只监听127.0.0.1；
完整参数、退出码和预算见[在线服务](ONLINE_SEARCH.md)、[客户端](NETWORK_CLIENT.md)。

## 协议和验收入口

线格式唯一入口为[协议版本1](PROTOCOL.md)，覆盖24字节头、四命令、状态码、黄金字节、
Body和关联规则；业务字段及成功结果见[在线schema](ONLINE_SEARCH.md)，SERVER_INFO见
[客户端合同](NETWORK_CLIENT.md)。应用帧、一次 send/recv 和 TCP 段各有不同边界。

| 必做门禁 | 合同与实现入口 | 验证入口 |
|---|---|---|
| 帧头、增量解码、严格 JSON 与有界收发 | [协议](PROTOCOL.md)、[codec](FRAME_CODEC.md)、Connection | codec、frame_decoder、connection读写及客户端组 |
| 固定线程归属和 fd 移交 | [Main](MAIN_REACTOR.md)、[多Sub](MULTI_REACTOR.md) | multi_reactor、eventfd与handoff组 |
| 真实业务和迟到结果身份 | [在线闭环](ONLINE_SEARCH.md)、[结果唤醒](COMPLETION_WAKEUP.md) | online_search、connection_identity、completion_wakeup |
| 单在途、半关闭、慢输出与满队列 | [单在途](SINGLE_INFLIGHT.md)、[背压](OUTPUT_BACKPRESSURE.md)、[饱和](WORKER_SATURATION.md) | single_inflight、output_backpressure、worker_saturation |
| timerfd与局部期限 | [deadline](DEADLINES.md) | deadline_queue、deadline_timer、sub/online_deadlines |
| 版本/参数隔离的成功Body缓存 | [LRU](VERSIONED_LRU.md) | versioned_lru与service_cache组；默认关闭 |
| 四命令客户端和正常/故障关闭 | [客户端](NETWORK_CLIENT.md)、[退出](GRACEFUL_SHUTDOWN.md) | client、graceful、online故障组 |
| 组合故障、并发与线程/fd回收 | [测试矩阵](V2_TESTING.md) | v2_fault_concurrency单/双Sub及各专项 |

Debug/Release 分开构建，按 README 执行完整 CTest；准确名称与数量以该源码
`ctest --test-dir build/debug --show-only=json-v1` 为准。行为断言在 Release 中仍有效。
ASan/UBSan 与 TSan 分开使用独立 Debug 构建；全局 new/delete 替换的故障目标需按工具
相容性选取，相关集成通过不代表全项目插桩。工具只覆盖受测执行，仍需身份、顺序和资源断言。

## 小型基准口径

[基准脚本](../tools/v2_baseline.py)只连接127.0.0.1，用一个持久 TCP 连接串行执行选定
命令：先 SERVER_INFO，再默认10次预热、200次计量。每帧核对头、关联号、成功状态、
长度、UTF-8/JSON与必要业务字段；任何错误非零退出，不输出成功统计。不重试、不管线、
不并发；SEARCH/SUGGEST 固定 top_k=5。`--requests`、`--warmup`、`--timeout-ms`可调整。

客户端用 perf_counter_ns 计量编码、send、完整接收、JSON及必要响应准入；分位数采用
nearest-rank。吞吐是计量循环完整成功响应数/墙钟时间，包含循环开销；连接、INFO、预热、
输出报告不在窗口内。原始 latency_ns、环境、请求、服务元信息和脚本SHA保存在JSON中。
每次交换有固定总期限，进展不续期；它不是硬实时承诺，也不证明不存在后续多余字节。

运行时另保存源码提交/diff、程序SHA、编译器/配置、输入与快照清单SHA、服务参数及最终
报告，才能定位本次观测。SERVER_INFO 的 snapshot_version 是快照身份，build_version
是声明，不等于运行程序Git身份。错误、非空响应和黄金正确性由专项测试共同覆盖，基准
自身不计算独立排序参考。

本页配套的[原始基准观测](baselines/v2-loopback.json)记录本次具体条件与原始样本。
这是阶段必需的小型基准，不能当作容量上限、生产QPS、并发尾延迟或缓存收益。整体项目完成后
另做系统性能评估，包括关闭/冷/热缓存、并发、内存、锁竞争及数据规模；本次不提前实施。

## 保留的限制与交接

缓存和空闲/请求期限默认关闭；可通过[启动配置](SERVER_CONFIG.md)、对应CLI参数或C++配置启用。
队列/Body/输出/工作预算不等于全局RSS硬上限。固定worker和Sub不动态扩缩；没有任务取消、
single-flight、TTL、Redis、TLS、DNS、HTTP或全局任务字节准入。
V2封板时没有在线热切换；后续已提供[后台加载](SNAPSHOT_LOADER.md)和[显式C++安全发布](SNAPSHOT_PUBLICATION.md)，
正式CLI仍没有reload/信号触发入口，默认启动版本行为保持。
V2封板时日志尚未接入；现生产服务已有[结构化日志](LOGGING.md)，默认info启用，可显式off。
V2封板时指标尚未接入；现生产服务已有[最小指标](METRICS.md)。现生产信号入口已由[Main signalfd](SIGNALS.md)统一观察，继续使用原优雅关闭屏障。

网络排空不证明对端收到，RST/截止可留下部分响应；客户端以完整准入决定成功。有限调度和
无TSan报告不证明所有调度、无死锁或零缺陷。局部loopback与小型原创语料不证明真实私有数据
质量、公网、真实OOM或系统性能。V1资源相容认证和top-k效率复评仍保留各自后续范围。

工程基线与本人学习分开验收。学习者后续沿“连接移交→异步结果回原Sub→背压/期限/退出”
回放，亲自完成预测、GDB观察、故障及代表性修改；本页与自动测试不证明本人已经掌握，
不代替后续调试学习包或授权进入下一模块。
