# 固定 WorkerPool

`concurrency::WorkerPool` 复用[有界TaskQueue](TASK_QUEUE.md)，提供固定线程的启动、独占任务执行、异常隔离与关闭排空。CMake 目标 `siftwing_worker_pool` 声明线程与队列依赖，公共合同以 [worker_pool.hpp](../include/siftwing/concurrency/worker_pool.hpp) 为准。

`WorkerTask` 是具有虚析构与 `execute()` 的基础类型。生产者先构造拥有输入与依赖生命周期的任务，以 `unique_ptr<WorkerTask>` 左值提交；任务不得借用 Connection 或以 fd 数字代表连接。具体 SearchTask、Completion 数据、业务错误响应和网络接入属于后续模块；当前组件没有正式业务调用方。

## 启动与拥有

构造参数为固定 1—64 个 worker 和正待执行容量。构造成功意味着所有 worker 已进入启动门禁并已统一放行，不保证每个线程已经进入 `wait_pop`。零容量、非法线程数、分配或线程创建失败会抛异常。部分启动失败放行退出门禁，join 已创建线程后传播原异常；同步设施或回滚 join 无法完成属于不可恢复错误。

成功提交才移走源；关闭、空源、队列满按该顺序拒绝并保留源。提交可等待 mutex，不等待空位；成功任务可能在提交返回前已经执行和销毁。容量只算尚未取出的任务，不包括执行中任务、任务字节或 RSS。生产者仍须对拒绝结果实施自己的策略。

一个 worker 独占取出的任务，调用 `execute()` 一次，随后在 worker 上销毁任务。队列/报告/join 锁不包围用户执行或析构。单 worker 保持 FIFO 执行，多 worker 仅保证队列 FIFO 移除，不保证完成次序或公平性。

## 异常与观测

`execute()` 抛出的任意异常均被隔离，任务不重试，worker 继续消费。报告在同一锁内记录饱和的 `uint64_t` 成功/失败计数，只保留首个记录异常的 `exception_ptr`；可由调用者重抛，不自动生成业务响应。多 worker 的首因按报告锁记录顺序决定。异常引用的最后释放可发生在控制线程，不能把异常对象的销毁归属与任务对象混同。

`report()` 是计数和首异常的一致快照，`queue_status()` 是队列的一致快照，两者不形成原子总状态。队列空不代表任务完成，统计增加也可能先于任务析构。`join()` 返回后才保证全部已接收任务执行、销毁并获得最终报告。pool 的同步设施异常在 worker 边界会 terminate，公共初次锁错误可传播；不能将基础设施灾难记成普通任务失败然后丢弃队列。

## 关闭与销毁

`request_stop()` 幂等关闭入口并唤醒消费者，保留已接收条目，不等待线程或外部调用者。与提交竞争时，以队列同锁提交点决定拥有者。`join()` 先关闭，再等待所有 worker 排空和退出；多控制者 join 串行，重复调用安全。

本池 worker 调用自身 `join()` 会在获取 join 锁前抛 `logic_error`，避免控制者持锁等 worker、worker 反向等锁；拒绝不隐式关闭入口。worker 可以请求停止或再次提交。跨池或其他依赖的等待环由调用者防止。

析构在没有外部调用者时自动 close/drain/join；禁止从本池 worker 销毁 pool。停止不取消执行中的任务，没有截止时间；阻塞任务可能令 join 或析构无限等待。销毁前须撤销外部入口并等全部 producer/stop/观测/join 调用完整返回，含提交的锁外通知。join 只证明 worker 已回收，不证明外部生产者已静止。

## 验证边界

三个真实 CTest 验证单 worker 顺序、满/关闭拒绝与源保留、异常继续执行、首异常、锁外销毁、自停止、自 join 与并发 join；多生产者检查每个任务的执行次数、提交前普通字段可见性、并发关闭的拥有关系；启动逐次分配与初次锁错误注入，通过Linux实际tid识别四个预热worker、join后确认其条目消失；随后按包含运行时辅助线程的精确`/proc/self/task`基线，以5秒期限观察每次部分启动回滚无线程遗留。join完成不要求Linux目录观测立即同步。

故障注入包装当前工具链的构造者 `new` 和直接 mutex 调用，不声称拦截标准库 DSO 内部 `pthread_create`/条件等待或验证真实资源耗尽。Debug/Release 全量及专项 ASan/UBSan、独立 TSan 的实际结果由验证日志记录；这些测试不证明任意调度、公平性、生产容量、硬实时或业务搜索闭环。
